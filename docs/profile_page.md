# Suitora — User Profile Page Documentation

This document defines the complete data model, UI structure, and implementation plan for the Suitora user profile page. The profile page collects personal measurements and preferences to enable accurate AI-powered body size prediction, clothing compatibility scoring, and virtual try-on.

---

## 1. Overview & Purpose

The profile page serves as the user's personal body measurement hub. The data collected here directly feeds into:

- **Body size prediction**: Estimating height, weight, and proportions from user-submitted measurements and photos
- **Clothing size recommendation**: Mapping body measurements to standard clothing size charts (XS–4XL, numeric sizes, etc.)
- **Virtual try-on calibration**: Improving the accuracy of generated try-on images
- **Compatibility scoring**: Refining body fit, style match, and color harmony scores
- **Personalized recommendations**: Tailoring suggestions based on body shape and style preferences

## 2. Profile Data Model — Complete Field Reference

### 2.1 Basic Account Fields

These are core identity fields, typically set during registration and editable from the profile page.

| Field | Type | Required | Description | Example |
|-------|------|----------|-------------|---------|
| `id` | `TEXT (UUID)` | ✅ | Unique user identifier | `"usr_a1b2c3d4"` |
| `name` | `TEXT` | ✅ | Display name | `"Jane Doe"` |
| `email` | `TEXT` | ✅ | Email address (unique) | `"jane@example.com"` |
| `avatarUrl` | `TEXT` | ❌ | Profile photo URL | `"https://.../avatar.jpg"` |
| `phone` | `TEXT` | ❌ | Contact number | `"+1-555-0123"` |
| `dateOfBirth` | `TEXT (ISO date)` | ❌ | Date of birth for age-based size estimation | `"1995-06-15"` |
| `gender` | `TEXT` | ❌ | Gender identity for size chart mapping | `"female"` / `"male"` / `"non-binary"` / `"prefer-not-to-say"` |

### 2.2 Body Measurement Fields (Manual Entry)

These are measurements the user can optionally enter manually. When provided, they serve as ground-truth calibration for the AI estimation system (confidence = 1.0).

| Field | Type | Unit | Required | Description |
|-------|------|------|----------|-------------|
| `height` | `REAL` | cm | ❌ | Total standing height |
| `weight` | `REAL` | kg | ❌ | Body weight |
| `chestCircumference` | `REAL` | cm | ❌ | Chest/bust circumference at fullest point |
| `waistCircumference` | `REAL` | cm | ❌ | Natural waist circumference (narrowest point) |
| `hipCircumference` | `REAL` | cm | ❌ | Hip circumference at fullest point |
| `shoulderWidth` | `REAL` | cm | ❌ | Biacromial width (shoulder to shoulder) |
| `inseamLength` | `REAL` | cm | ❌ | Inner leg length (crotch to ankle) |
| `armLength` | `REAL` | cm | ❌ | Sleeve length (shoulder to wrist) |
| `neckCircumference` | `REAL` | cm | ❌ | Neck circumference (for collared shirts) |
| `footLength` | `REAL` | cm | ❌ | Foot length (heel to longest toe) |
| `footWidth` | `REAL` | cm | ❌ | Foot width at widest point |
| `shoeSize` | `TEXT` | US/EU/UK | ❌ | Shoe size in preferred system |
| `bustCupSize` | `TEXT` | — | ❌ | Bra cup size (e.g., "34B", "36C") — for tops/dresses |

**Validation Rules:**
- All length measurements must be > 0 and < 300 cm
- `height` must be between 50 cm and 280 cm
- `weight` must be between 10 kg and 350 kg
- `shoeSize` should be accompanied by the sizing system (e.g., `"US 8"` or `"EU 39"`)
- Measurements should pass logical consistency checks (e.g., `waistCircumference` < `hipCircumference`)

### 2.3 AI-Estimated Fields (Read-Only / Auto-Populated)

These fields are generated by the AI body estimation pipeline (see `lib/ai/body-estimation.ts`) when the user uploads a full-body photo. They are read-only in the UI but can be overridden by manual entry.

| Field | Type | Unit | Description |
|-------|------|------|-------------|
| `estimatedHeight` | `REAL` | cm | AI-predicted height from photo analysis |
| `estimatedHeightConfidence` | `REAL` | 0.0–1.0 | Confidence level of height prediction |
| `estimatedWeight` | `REAL` | kg | AI-predicted weight |
| `estimatedWeightConfidence` | `REAL` | 0.0–1.0 | Confidence level of weight prediction |
| `bodyShape` | `TEXT` | — | Categorical body shape classification |
| `bodyShapeConfidence` | `REAL` | 0.0–1.0 | Confidence level of shape classification |
| `skinTone` | `TEXT` | — | Detected skin tone category |
| `faceShape` | `TEXT` | — | Detected face shape category |
| `bmiCategory` | `TEXT` | — | Estimated BMI range (underweight / normal / overweight / obese) |

**Body Shape Enum:**
```
"rectangle" | "pear" | "apple" | "hourglass" | "triangle" | "inverted-triangle"
```

**Skin Tone Enum:**
```
"warm" | "cool" | "neutral" | "olive" | "deep"
```

**Face Shape Enum:**
```
"round" | "oval" | "heart" | "square" | "diamond" | "oblong"
```

**BMI Categories:**
```
"underweight"   // BMI < 18.5
"normal"        // 18.5 ≤ BMI < 25
"overweight"    // 25 ≤ BMI < 30
"obese"         // BMI ≥ 30
```

### 2.4 Derived & Computed Fields

These are not stored directly but computed on-the-fly from the measurement fields.

| Field | Formula / Logic | Purpose |
|-------|----------------|---------|
| `bmi` | `weight / (height / 100)²` | Quick health reference |
| `waistToHipRatio` | `waistCircumference / hipCircumference` | Body shape classification |
| `shoulderToWaistRatio` | `shoulderWidth / waistCircumference` | Torso proportion for fit scoring |
| `predictedSizes` | Mapping of measurements → brand size charts | Size recommendations per retailer |
| `shoeSizeUS` / `shoeSizeEU` / `shoeSizeUK` | Conversion from `footLength` or `shoeSize` | Multi-system shoe size display |

## 5. Size Prediction Engine — How Measurements Map to Clothing Sizes

The core purpose of collecting body measurements is to predict the correct clothing size across different brands and sizing systems.

### 5.1 General Size Chart Mapping

| Measurement | XS | S | M | L | XL | XXL | XXXL |
|-------------|----|---|----|----|-----|------|------|
| Chest (cm) | 81–86 | 86–91 | 91–97 | 97–102 | 102–107 | 107–112 | 112–117 |
| Waist (cm) | 66–71 | 71–76 | 76–81 | 81–86 | 86–91 | 91–97 | 97–102 |
| Hip (cm) | 86–91 | 91–97 | 97–102 | 102–107 | 107–112 | 112–117 | 117–122 |
| Inseam (cm) | 74–76 | 76–79 | 79–81 | 81–84 | 84–86 | 86–89 | 89–91 |
| Sleeve (cm) | 81–84 | 84–86 | 86–89 | 89–91 | 91–94 | 94–97 | 97–99 |

### 5.2 Footwear Size Conversion

The `footLength` measurement is the most reliable predictor of shoe size.

| Foot Length (cm) | US (Men) | US (Women) | EU | UK |

| 24.5–25.0 | 7 | 7.5 | 38 | 5 |

| 29.5–30.0 | 12 | — | 47 | 10 |

### 5.3 Prediction Algorithm

The size prediction engine (`lib/ai/size-prediction.ts`) will:

1. **Collect all available data points** — manual measurements (highest priority), AI-estimated values, derived calculations
2. **Determine the user's primary body frame** — using shoulder width, chest, waist, and hip for tops; inseam and waist for bottoms; foot length for shoes
3. **Map measurements to size charts** — using the general chart above with brand-specific offsets
4. **Return a confidence-weighted recommendation** — with fallback for missing measurements

```typescript
interface SizePrediction {
  topSize: { size: string; confidence: number };
  bottomSize: { size: string; confidence: number };
  dressSize: { size: string; confidence: number };
  shoeSize: { us: string; eu: string; uk: string; confidence: number };
  measurementsUsed: string[];  // which fields were available
  missingMeasurements: string[]; // which fields would improve accuracy
}
```

### 6.2 Measurement Entry UX

- **Status indicators** next to each field:
  - `✓ Manual` — value entered by user (highest authority)
  - `○ AI est.` — value estimated by AI from photo
  - `— Empty` — no value yet
  - `⚠ Needs update` — value is stale or low confidence
- **Unit toggle**: cm/kg (metric) or ft/in/lbs (imperial) with automatic conversion
- **Visual measurement guide**: Clicking a field opens a tooltip showing where/how to measure (illustrations)
- **Bulk import**: Option to import measurements from a photo or supported wearable device (Apple Health, Google Fit)

## 7. API Endpoints

### `GET /api/user/profile`
Returns the authenticated user's profile with all measurements and preferences.

**Response:**
```json
{
  "user": { "id": "usr_123", "name": "Jane Doe", "email": "jane@example.com" },
  "profile": {
    "height": 165.0,
    "weight": 58.0,
    "bodyShape": "hourglass",
    "selfImageUrl": "https://...",
    "styleTags": ["casual", "minimalist"],
    "fitPreference": "regular",
    ...
  }
}
```

### `PUT /api/user/profile`
Updates profile fields. Accepts partial updates — only send changed fields.

**Request:**
```json
{
  "height": 167.0,
  "weight": 60.0,
  "styleTags": ["casual", "vintage"]
}
```

**Response:** Returns the updated full profile.

### `POST /api/user/self-image`
Uploads a new full-body photo for AI body estimation.

**Request:** `multipart/form-data` with the image file.

**Response:**
```json
{
  "selfImageUrl": "https://...",
  "estimatedHeight": 165.0,
  "estimatedHeightConfidence": 0.92,
  "estimatedWeight": 60.0,
  "estimatedWeightConfidence": 0.86,
  "bodyShape": "hourglass"
}
```

### `POST /api/user/profile/estimate`
Triggers AI re-estimation using the latest self-image without uploading a new one.

**Response:** Same as self-image upload but without the image URL.

## 10. Edge Cases & Validation

| Scenario | Handling |
|----------|----------|
| **User has no measurements** | Show empty state with CTA to add measurements or upload a photo |
| **User has only AI estimates** | Display with confidence badges; prompt to add manual measurements for higher accuracy |
| **Measurements conflict** (manual vs AI) | Manual measurements always take precedence; show AI values in subdued text |
| **Out-of-range values** | Clamp to valid range and show validation warning |
| **Missing critical measurements** | Size prediction shows "Insufficient data" with list of suggested fields to add |
| **Self-image deleted** | Clear AI estimates; prompt user to re-upload |
| **Unit conversion** | Store all values in metric internally; convert for display only |
| **Incomplete form save** | All fields are optional — save partial data without errors |
| **Photo upload failure** | Show error with retry; do not clear existing self-image |
